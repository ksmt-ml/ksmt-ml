# Фаза 05 · validation, lock, holdout
Протокол записан до исходов поиска/validation. Тестовых входов и зерна ещё нет.

По каждой настройке из двух лучших корректных TRAIN результатов каждого
метода и зерна оцениваются две парные перестановки на validation, включая A
и фиксированный одиночный TRAIN-контраст. Конфигурации с неверным ответом,
ошибкой или неполным сеансом не выбираются. Лучший допустимый претендент
метода/зерна выбирается по равновесовому по семьям PAR2, tie-break по ID.
Если претендента нет, метод представлен A. Решение о допустимости внедрения
отдельно: validation выигрыш >5% и минимум 20 мс PAR2 либо добавочный
решённый сеанс без потерь. Эта проверка не мешает сравнить корректного
зафиксированного претендента на test, когда validation не поддерживает
внедрение. На тесте не выбираются новые параметры и победители по зерну.

До генерации test записывается immutable lock с SHA-256 плана, validation,
первых двух TRAIN вариантов, verifier и списка выбранных флагов.
Код генераторов и схема разделения записываются в precommit. Первый
seed в Linux getrandom создаётся только после успешной записи lock и
сохраняется для воспроизведения. Разные производители открываются
раздельно. Sol видит исключительно анонимный TRAIN handoff.

Основной test — свежие независимые проекты. Для ограничений: прямоугольные
полосы, партии печи, покрытие смен, параллельный DAG, разделение
конфликтующих контейнеров и слияние двух полос. Соседние пороги и размеры
внутри проекта считаются одним кластером. Для HW конструкции
объясняются отдельно; совпадение области (арифметика, управление) не
делает две схемы репликами. Отдельно показать базовый comb/seq срез.
Две блокированные перестановки с ротацией ядер. Test cap совпадает с
TRAIN. Для BMC нативный SMT transcript и оракул проверяются дополнительно.
Любое противоречие оракула публикуется и карантинируется до агрегации. Нулевые
тайм-ауты оракула не требуются, если есть независимый точный оракул. Несогласие
оракула не используется как способ подобрать настройку на test.

Главные оценки: средний по кластерам PAR2, уникальные решённые сеансы,
подтверждённые ответы, raw-ошибки и парные разности. При сравнении Sol со
SMAC/random сначала усредняются повторы и сравнимые зерна внутри каждого
семейства, затем ресемплируются целые семейства (10 000 парных повторов,
зафиксированное зерно). Небольшое число кластеров явно указывается.
Общие конфиги переиспользуют один замер внутри блока, совпадение config
не превращает один результат в дополнительный сеанс или кластер.
