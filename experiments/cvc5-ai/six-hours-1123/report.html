Ответ на вопрос о настройке

На исходном живом эксперименте Sol и SMAC выбрали заводские настройки cvc5. Проверенные альтернативы не прошли одновременно пороги времени, качества и надёжности. Выбор заморожен до перезагрузки. В закрытом тесте у меток Sol и SMAC одинаковый cvc5.

Ускорение порядка 2% в исходной схеме трудно различить. Фиксированный лимит шагов повышает сопоставимость, и совпавшие счётчики ещё требуют проверки траектории. Прямые FP→BV преобразования дают отдельный отказ адаптера. Нативные флаги могут менять смысл после первого check.

Свежая нативная репликация на 48 программ и четырёх семействах не подтвердила перенос ускорения BV флагов с сохранением ответов. Неустойчивые эффекты и различия исходов учтены до допуска нового поиска.

У исходной поисковой выборки не было отказов STORE_ALL, которые появились на другом проекте в закрытом тесте. Контроль Java подтвердил потерю достижимых исходов. Это конкретный случай, где состав клиента и ограничения решателя меняют качество измерения.

В опытных Java задачах настройка arrays-exp=true подняла полноту исходов с 32/96 до 96/96 и устранила все 356 ответов STORE_ALL default. Это восстановление работы клиента. Разница PAR2 в первую очередь отражает исчезновение штрафов за UNKNOWN.

На четырёх новых закрытых семействах одиночное правило arrays-exp=true дало 32/32 полных наблюдений против 0 у default. Две комбинации дали те же множества исходов. Интервалы времени check на сопоставимых наблюдениях включают равенство с одиночной опцией.

На этой узкой задаче Sol подтвердил полезный вектор в 3 из 3 раундов, random в 2 из 3, исходный SMAC в 1 из 3. Третий раунд SMAC прервался до оценки кандидатов. После восстановления его результата счёт SMAC составил 2 из 3. Результат описывает поиск в малом пространстве и не устанавливает преимущество адаптивного метода над заранее известным правилом.

Экспериментальный обход ограничения FP→BV восстанавливает обычные диагностические исходы. Тест на полезную нагрузку NaN выявил ложные Java-свидетельства, поэтому для этих операций требуется отдельная модель сохранения битов.

На независимой библиотечной панели static-learning=false остался вне допуска. При стеновом бюджете сохранилось 94,08% путей default. При фиксированных шагах увеличилось число solver timeout. Заводская настройка остаётся опорой для широкого живого профиля. Подтверждённое условие STORE_ALL даёт отдельный сценарий для проверки arrays-exp=true.

Для независимого переноса использованы классы Java библиотек и отдельные вычислительные семейства с оракулами. В локальных рабочих копиях TSA не обнаружен.

На 47 строго совпавших тройках контрольная доза дала отношение выявленного к внесённому 0,951 [0,618; 1,164] при таймере CPU потока и 0,699 [-0,017; 1,222] при wall. Для оценки малых различий check полезны сравнения на одинаковой работе с отдельным временем CPU. Время JVM и покрытие остаются самостоятельными критериями.

Живой ресурсный предел 32000 дал 36 путей против 64 при заводском cvc5. Предел добавил 4 ресурсных UNKNOWN в коротком пилоте. Сокращение сырого времени сопровождалось меньшей выполненной работой.

При пределе 256000 счётчики путей сравнялись. Осталось 2 ресурсных UNKNOWN. Совпали 5 из 8 полных трасс. На точном общем префиксе отношение времени check 0,833 [0,817; 1,310].

В нативном сравнении объявление ALL меняет только доступные теории. На 22 новых программах CPU на совместно правильных вырос до 1,005 [1,004; 1,094]. Эти потоки не воспроизводят смешанный живой вход USVM, где выбор узкой логики потребовал бы надёжной классификации всех запросов.
