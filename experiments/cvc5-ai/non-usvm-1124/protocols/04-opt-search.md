# Фаза 04 · поиск для статических ограничений
Скрининг 20 экземпляров × 2. Заводской решает 34/40, отключение static-learning
и включение ite-simp решают 36/40. Дополнительный ответ — exact-cover-24
на пороге optimum−1, его независимо доказывает алгоритм перебора подмножеств.
Улучшение PAR2 у ite-simp 18,2% (1,977 против 2,416 с), A/A′ отличается
приблизительно на 0,4%. Это TRAIN сигнал, сравнение на тесте остаётся закрытым.
Пара из identical-bins и shift-windows, где вся панель дважды достигла
предела, остаётся в скрининге и исключается из целей поиска по этому правилу.
Все прочие цели сохраняются. Независимые источники ограничений имеют
одинаковый вес, затем усредняются задачи в кластере.

Опции поиска — восемь двоичных групп, QF_LIA и тот же CLI. arith-prop=both
не включён, так как конфликтует в одном конфиге с arith-prop=none.
Limits, решатель, счётчик потоков, модели, логика, seed решателя и команды
входа неизменны. MENU не передаётся как измеренный warmstart.
Фиксированный TRAIN контраст для validation/test — ite-simp.

Три парных раунда: 2201, 2202, 2203, каждый с одновременными default,
нативным SMAC3, Sol (до 3 ID за один новый изолированный ответ с обратной
связью между пакетами) и случайным без возвращений. Каждому 1320 с
(22 минуты) и один worker на отдельном физическом ядре; ротация CPU 12–15.
Модель, запуски неуспешных предложений и аудит входят в бюджет.
Общий первый измеренный вариант — заводской, дальше у random равновероятная
перестановка, SMAC получает тот же скаляр, Sol получает анонимный список
предложений, стоимости, счёт решённых и признак пригодности.
В ходе окна baseline измеряется повторно только на default для контроля
дрейфа, один сеанс на экземпляр в каждом пакете. Отсечённые незавершённые
пакеты сохраняются и не передаются оптимизатору.
Языковые обозначения и ключи доступны как описание задачи, ни исходных
данных, ни имен кластеров, ни validation/holdout Sol не получает.
