# 10. Где расходятся полные траектории

После малой доли одинаковых SHA-256 в 04b разделяем трассу на три измеряемые последовательности. Порядок полных путей состояний USVM, активный стек утверждений и допущений для каждого check и порядок иных операций solver. SHA-256 проверяет наблюдаемую последовательность. Состояние backend и смысловая эквивалентность при различающихся именах символов остаются отдельными вопросами. Измеряем первые 512 шагов/запросов и итоговую цепочку целиком. Этот опыт направлен на происхождение расхождений, времена трассировки используются как диагностика.

Для каждого проекта из 01 фиксируем до запуска до трёх методов: чистый повтор с равной полной трассой, совпавшие итоговые счётчики при разной полной трассе, различающийся объём работы. В каждом доступном слое предпочитаем метод с большим числом check и фиксированный тай-брейк. Повторяем независимый свежий JVM с 4000 шагами, seed 0 и 71, три повтора. Плечи FORK_DEPTH A/A и DFS, один рабочий поток на ядро; одинаковый default cvc5 во всех. Рандомизируем порядок и запечатываем манифест. Публикуем ошибки, UNKNOWN и долю различий по каждому уровню. Останов по расписанию и до общего дедлайна.
