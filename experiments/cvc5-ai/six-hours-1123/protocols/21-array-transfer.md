# 21. Перенос исправления STORE_ALL в независимые библиотеки

Запускается, если диагностический 18 проходит допуск качества. Дополнительные общие Java библиотеки отбираются до динамики по локальному байткоду. Метод должен иметь обычную примитивную или одномерную массивную сигнатуру из статического фильтра 12, операции создания локального массива, индексированной записи и чтения в том же методе. Зарезервированные проекты и классы, уже выбранные для местных живых опытов, исключаются. До трёх классов на проект, три JVM-повтора, два seed. Одна библиотека считается одним независимым проектом. Малый доступный набор отмечается как пилот. При отсутствии двух подходящих проектов эксперимент сохраняет отчёт о статическом отборе.

Default A/B, cvc5 `arrays-exp=true` и штатный Z3. Предел 4000 шагов, solver 1,6 с, тот же KSMT. Вся траектория инструментирована. Первичная величина — число и распределение STORE_ALL, UNKNOWN, путей и покрытия по проектам. Ранее исследованная причина предсказывает исчезновение STORE_ALL при E, если такой запрос возникает в A/B. Изменение измеренной работы оценивается отдельно, exact-prefix время применимо лишь при совпавшем наблюдаемом префиксе. Для этих библиотек нет полного независимого Java оракула, Z3 проверяет перенос на уровне наблюдаемых состояний и ответов. Сбор останавливается после фиксированного расписания или до общего дедлайна.
