# 08. Условный повторный живой поиск

Запуск разрешён после проверки полных компактных блоков 04b. Сначала определяем чистые трассированные A/B пары с одинаковым полным SHA-256, всеми счётчиками и не менее пяти check. Один исходный метод относится к одному проекту. На этой общей выборке каждый кандидат должен сохранить весь наблюдаемый объём работы и без ошибок. Допуск для нового сравнительного поиска требует хотя бы двух недефолтных одиночных переключателей, у которых суммарное check_ms не выше 95% среднего A/B, анализ не выше 102% среднего A/B, и преимущество check видно хотя бы в двух проектах. Требуется SMT доля ≥25% либо сохранение общего времени метода. Повторный скрининг или отсутствие допуска фиксируются до любых динамических результатов указанного test.

План при допуске. Низкая ступень train использует по одному воспроизводимому методу в каждом допущенном проекте (больше checks, затем неизменяемый тай-брейк). Кандидаты строятся из прошедших переключателей и проверенных совместимых комбинаций. Sol, нативный SMAC 2.4.0 ask/tell и random работают в трёх отдельных повторениях с заранее зафиксированными seed и сбалансированным порядком. Каждый получает 640 секунд train, включая время реальных запросов модели, и 280 секунд на validation. Не более 10 вызовов Sol на повтор и 65 с на вызов. Вложенный Codex видит только анонимизированные train показатели и точное пространство. Полная оценка сравнивает вариант с default в общем JVM, свежая машина на каждый анализ. Три прогрева, фиксированные 1500 шагов, версии и параметры из 04b.

Validation использует до двух лучших допустимых вариантов каждого плеча с новым default и одинаковым бюджетом. Проекты train, validation, test непересекающиеся из статического frozen research-split. Validation и test заранее используют одну статическую процедуру; модели их не видят. Критерии качества: ≥98% суммарных путей, рёбер и шагов относительно парного default, ≥95% путей по проекту, ≥−1 п.п. покрытия, без роста штрафов, UNKNOWN, таймаутов, исключений шага и незавершённых JVM. Нормированные check_ms минимизируются при эквивалентности счётчиков ≥95% методов и полном времени анализа ≤102%. Чтобы выбрать вариант, check_ms должно быть ≤95% контрольного в train и validation. Если выбора нет, идентичность default фиксируется.

В тесте 4 JVM повторения на проект (два seed), внутри блока рандомизированы точные уникальные векторы. Совпавшие имена стратегии используют один наблюдаемый вектор, сопоставимый cvc5 на том же рабочем классе и seed. Оценка по кластерам проектов, с полной таблицей ошибок. Бюджет приобретения защищён до 09:21, без расчёта незапущенных сценариев. Без достаточного допуска проводится отдельная диагностика, без передачи тестовых результатов Sol.
