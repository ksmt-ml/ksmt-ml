# 20. Условный поиск на живом классе массивов с исчерпывающим оракулом

Этот опыт проверяет выбор конфигурации после диагностированного отказа STORE_ALL. Допуск оценивается по независимому 18. Нужны два разных подтверждённых вектора с `arrays-exp=true`, у которых в двух или более семействах стало больше полных правильных программных наблюдений, при отсутствии потерь полного оракула по каждому семейству, неверных свидетелей и сбоев JVM. Общий выигрыш каждого вектора — хотя бы восемь полных программных наблюдений. Вся серия 18 должна быть завершена. Эффект рассматривается по достижимым Java исходам. Эта проверка допуска отделена от прежних порогов производительности.

Четыре алгоритмических семейства в каждой части, два новых класса на семейство. Семейства целиком лежат в одном из train, validation, test. Классы, точное расписание методов и исчерпывающий Java оракул везде замораживаются до первого измерения 20. Исторические методы, реальная закрытая панель и данные 18 отсутствуют в новых model prompt. Модель получает числовой train, а имена семейств заменяются стабильными номерами P1–P4. Опции по одному переключателю и парами: arrays-exp=true, arrays-eager-index=false, static-learning=false. После нативного контракта точные векторы доступны всем стратегиям. Замороженная диагностическая политика E всегда применяет только arrays-exp=true. Это сравнение с default A и фиксированным E проверяет, сколько даёт сам поиск в зависимости от знания механизма.

Sol gpt-6.2-sol через train-only вход, настоящий SMAC 2.4.0 ask/tell и uniform random. Три независимых раунда выбора, вращающийся порядок. На стратегию в каждом раунде 270 с train включая контроль A/B, оценку кандидатов и фактическую задержку Sol. Максимум пять удалённых запросов на раунд, по 55 с максимум. 140 с валидации, максимум два допущенных train пакета. Одинаковый живой исполнитель выдаёт явные шаги, пути, рёбра, покрытие, Java результаты, UNKNOWN и ошибки. После заморозки выбора test выполняется локально по четырём семействам, четыре свежих повтора с двумя seed и случайной ротацией точных уникальных конфигураций. A и E всегда присутствуют. На одном ядре в момент времени одна экспериментальная JVM.

Первичный результат — число полностью достигнутых множеств ожидаемых исходов и сопоставимость работы. Ни один неверный свидетель, сбой JVM или ухудшение числа полных наблюдений в любом семействе не может считаться улучшением. Для разумного допуска также требуется шагов, путей и рёбер хотя бы 98% и среднего покрытия минимум default −1 п.п., как у ранних опытов. Рост качества — минимум два дополнительных полных программных наблюдения на валидации. При равном качестве ускорение принимаем при равных проверенных итоговых счётчиках по каждой программе, без добавления UNKNOWN, при ≥5% уменьшении суммарного check времени на совпавшей работе. В исходном train ранжируем сначала полные исходы, затем измеренное check время. Интервальные оценки группируем по независимым семействам с повторами отдельно.
