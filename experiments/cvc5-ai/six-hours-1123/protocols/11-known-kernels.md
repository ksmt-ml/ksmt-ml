# 11. Вычислительные Java-ядра с полным конечным оракулом

После локализации FP ошибки проверяем другой доброкачественный закономерный клиент, целиком на штатной Java арифметике и локальных массивах. Шесть семейств: разложение произведения, частное и остаток, переносы при сложении, перезапись локального массива, знаковое представление и упаковка байтов. Четыре самостоятельных исходных класса на семейство. Каждый анализ принимает два int, которые сначала маскируются. Полнота возвращаемых классов заранее определяется перебором всех пар замаскированных аргументов реальным JVM. Контроль включает проверку полученных USVM свидетелей на локальном Java методе.

Заводские опции, повтор default A/B, bv-to-bool=true, static-learning=false, arrays-eager-index=false и bitwise-eq=true. Если контракт отклоняет вариант, записываем причину и не принимаем его в измерения. Четыре JVM-повтора на семейство, два seed, один свежий процесс на точный вектор/семейство/повтор, 3000 шагов без внутреннего wall стопа. Тот же cvc5/JNI, 1,6 с solver timeout, штатный селектор и фиксированное seed. Перед измерением журнал содержит точные Java файлы, байткод, оракул и назначение. Доверительные интервалы по семьям и программе, JVM повторы не увеличивают число независимых семейств.

Первичные критерии — полнота множества возвращаемых Java классов, неверные конкретные свидетели, UNKNOWN, ошибки и рабочие счётчики. Время сравнивается с парным default при одинаковой наблюдаемой работе. Составы методов различаются от прежних библиотечных программ. После сравнения не переносить эффект на другой тип программ без отдельного межсемейного теста. Останов по расписанию или по общему крайнему сроку.
