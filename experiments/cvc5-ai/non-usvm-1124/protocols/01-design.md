# Предрегистрация 01 · инвентаризация и пилот
Окно 24.11.2026 07:13:40–11:13:40 Europe/Moscow. Последний сбор к 11:08.
Фаза зафиксирована до первых измерений cvc5. Установка и проверки наличия уже начались.

- Основные источники: новые безопасные RTL проекты через реальный Yosys → yosys-smtbmc; новые модели ограничений для планирования и упаковки с отдельным точным проверяющим. Новые математические Dafny-программы проходят отдельный контракт, включая намеренно ложную спецификацию. Старые результаты Dafny используются лишь как диагностическая история. Публичные задачи только вторичные.
- Единица HW — один оригинальный BMC сеанс целиком, команды и ответы сохраняются. Для измерения основным будет живой frontend с переходником stdin/stdout без переписывания выражений. Для диагностики отдельно измеряется дословный CLI replay. SAT означает найденное нарушение, UNSAT на горизонте означает только отсутствие нарушения на нём. Внешний контроль Z3 плюс конструкция/симуляция.
- Единица ограничений — исходный статический SMT-LIB файл, одно решение задачи выполнимости. Сохраняется ожидаемый ответ от независимого точного алгоритма или проверяемой конструкции. Повторное сравнение с Z3 отдельно. Для Dafny единица — целая программа и все ожидаемые вердикты. Снятые с Z3 несовместимые или изменённые трассы не входят без проверки эквивалентности. Прирост на неверном доказательстве означает провал.
- Сопоставление на одном физическом ядре, перемешанные блоки, заводские опции A и A′ имеют ровно одну команду. Мелкое меню проверяется на TRAIN. Оценка PAR2 по целому сеансу, количество решённых сеансов и проверенных ответов. Таймаут, unknown, неполный вывод, ошибка и несовпадение оракула стоят 2T; неверный ответ отдельно дисквалифицирует вариант. Оценить A/A и нижнюю границу стоимости запуска.
- Разработка, изменение сложности и отбор источника используют только TRAIN. Сохранять все попытки и причины исключения. Разделение по независимым проектам/семействам, несколько масштабов и вариантов одного дизайна составляют один кластер. Validation не показывается алгоритмам. Тестовые входы материализуются после записи хеша завершённого lock. Другой процесс не имеет доступ к дереву проекта во время запросов Sol.
- Кандидат на полный поиск: улучшение на TRAIN превышает 15% и двойной типичный A/A либо есть хотя бы один подтверждённый дополнительный исход и отсутствуют ошибки. Если кандидатов несколько, приоритет реальному frontend, затем числу независимых улучшений. При отсутствии кандидата фиксируется короткий пилот поиска без претензии на выигрыш. Лимиты и конфигурации перед скринингом фиксируются отдельной записью; решение о продвижении перед validation.
- Поиск: официальная SMAC3 через ask/tell, случайный без возвращения, Sol GPT-6.2 интерактивно предлагает из того же пространства и получает только анонимные измерения TRAIN, default с тем же выделенным временем. Один закреплённый рабочий поток на алгоритм, одинаковая длительность, одинаковое начальное измерение A. Время модели внутри окна. Три парных зерна с ротацией ядер, ориентир 20–40 минут. Никаких подмен модели и скрытых повторов. После поиска сравнение двух лучших корректных кандидатов каждого метода с A на validation и фиксируем выбор по PAR2, при недостаточном эффекте выбираем A.
- TEST: повторить парные блоки с изменённым порядком, заявить отдельно живые данные, статику и публичные. Кластерный парный bootstrap по независимым проектам, указать число кластеров и эффект по каждому. Не выбирать победителя на тесте. Отдельно обсуждать настраиваемость и добавочную ценность Sol относительно SMAC/random.
- При возобновлении использовать завершённую запись по ID; незавершённые интервалы отметить и либо продолжить до старого дедлайна, либо явно создать новый запуск.
