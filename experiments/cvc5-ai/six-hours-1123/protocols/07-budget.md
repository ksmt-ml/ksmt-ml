# 07. Нативный лимит времени и воспроизводимый лимит ресурса

После шумных A/A и таймаутов сравниваем два механизма остановки в том же cvc5 JNI на математически проверяемых потоках. Четыре семейства, по шесть новых параметризаций. Заранее первые две программы каждого семейства служат только для калибровки. Остальные четыре составляют отдельный тест лимита. На обоих наборах фиксируется математический SAT/UNSAT оракул, который независимо проверяется локальным Z3.

W — tlimit-per 120 мс. R — ровно один из 500, 2000, 8000, 32000, 128000 внутренних единиц. Для R есть аварийный tlimit-per 800 мс. CPU 12–15, JNI, инкрементальность, модели, ядра общие. На калибровке минимизируем абсолютное различие числа правильных ответов W и R. При равенстве выбираем меньшее число ошибочных ответов, затем меньшее отклонение полного check wall. Парный и одинаковый исходный поток важнее скорости. Выбранный ресурс замораживается до теста. Для теста сравниваем запускаемую отдельно JVM серию и синхронные волны четырёх разных ядер. Рандомизированный порядок режимов на одинаковой программе и ядре. В каждом режиме четыре JVM-повтора на программу. Потоки с неполным оракулом описываются отдельно.

Первичный результат — смены SAT/UNSAT/UNKNOWN между повторами одного потока и режима. Сопоставление W/R по числу правильных ответов, CPU, стеночному времени, timeout, resourceout и ошибкам обязательно. Если native сборку не удаётся заставить соблюдать выбранную опцию или подтвердить хотя бы 12 тестовых программ, опыт завершается как техническая диагностика. Сбор до общего дедлайна. Изоляция работников сохраняется, на одном ядре одновременно только один измеряемый JVM.
