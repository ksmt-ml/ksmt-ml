Метрика суммируется по попыткам. Состояния — объекты, возвращённые штатным сборщиком COVERED_NEW. Терминальные события включают остановки состояний, а пути до выхода ограничены завершением входного стека. Исчерпание очереди, достижение цели покрытия и детерминированные лимиты считаются штатным завершением бюджета.

Дизайн и ограничения

Задание перед запуском зафиксировано в PREREG.md. Список методов составлен статически по байткоду публичных JAR. На проект взяты четыре метода с 1–2 и четыре с 3+ условными или switch-инструкциями. Проверены проектные и классовые пересечения с доступными прежними манифестами. Для re2j использованы восемь методов из пяти классов. В статическом отборе packageurl-java имел четыре метода из трёх классов, его заменил заранее записанный резерв commons-pool2. Старые данные использованы для дизайна и разграничения групп.

Для каждого проекта есть шесть повторов и все шесть порядков трёх режимов. Внутри блока методы идут в одном случайно выбранном порядке, режимы запускаются последовательно на одном ядре. Четыре работника закреплены за CPU 12–15, на каждом по 15 блоков, без SMT-соседей. Java 21, SerialGC, 2 ГиБ heap и один доступный процессор на JVM. Перед каждой серией одинаковая разминка из трёх синтетических методов.

Одинаковые параметры USVM: FORK_DEPTH, seed 0, 6 с на исследование метода, 1,6 с на проверку SMT, 1 с на операцию типов, порог 4000 шагов и 3500 шагов с последнего собранного состояния. Текущая реализация останавливает после превышения порога. Защита процесса — 150 с и проверка RSS 3200 МиБ после метода. Исключение интерпретатора считается ошибкой метода. Максимальный замеренный объём рабочего каталога в кампании 213,8 МБ при лимите 12 ГБ.

Версии и варианты

USVM commit 814a963354209421d36af758edbcec4295b081c4 и KSMT core 0.5.26. Для cvc5 пересобран только адаптер из тега 0.5.26, с shim для доступа к указателям и обработкой новых значений Kind. Оба режима cvc5 используют статический JNI из одного официального Linux x86-64 релиза и один Java API. Z3 4.13.0.0 работает через штатный JNI KSMT на тех же байтах из JAR. Все три режима выполнялись в процессе JVM.

Фабрика проверяла версию и значение упрощения, а после первой реальной проверки JVM сохраняла параметры и SHA-256 библиотек из /proc/self/maps. У cvc5 по умолчанию действует simplification=batch. Режим none устанавливает simplification=none. Вторая изменившаяся строка simplification-mode — алиас этой настройки. Общее состояние cvc5 после первой проверки включает incremental=true, produce-models=true, produce-unsat-cores=true, fp-exp=true, arrays-exp=false, seed=0 и tlimit-per=1600. Для Z3 значение random_seed=0 зафиксировано в справке созданного нативного солвера. Таймаут передаётся из одинаковых UMachineOptions штатному адаптеру. Запрос от клиента на Array/BV/UF/FP оставляет штатный общий солвер Z3, поскольку набор отсутствует в списке оптимизированных комбинаций KSMT 0.5.26.
