# Как установлены ответы

## Ограничения
Для каждого проекта задаётся оптимизационная спецификация, а SMT-LIB сравнивает
выполнимость при оптимальном пороге и при пороге на единицу ниже. Код независимого
точного решения работает с исходными длительностями, графами, интервалами и
массивами, отдельно от строк SMT. Проверка уже сохранённого свидетеля
`scripts/oracle_audit.py` восстанавливает его стоимость и ограничения из
`oracle.json`. Точный поиск даёт сертификат достижимого значения и исчерпывает
меньшие границы. Сохранённые узлы поиска и хеши привязывают оба порога к одному
кластеру. Z3 отдельно проверяет исходные SMT файлы, в том числе UNSAT сторону.

- Поточная линия. Перебор перестановок с нижней границей по окончанию префикса.
- Упаковка в одинаковые контейнеры. Ветвление по предмету и загрузкам с устранением симметрии.
- Смены с окнами. DP по подмножеству и самому раннему допустимому времени окончания.
- Job shop. Полный перебор топологических порядков заданий и ресурсов.
- Exact cover. Разветвление по непокрытому элементу и множеству доступных ним покрытий.
- Validation. Кратчайший гамильтонов путь с setup, две формы стабильного минимума взвешенного назначения.
- Holdout. Битовые маски ячеек для прямоугольников, DP совместимых партий печи,
  остаточный спрос для покрытия смен, перебор двух машин с рёбрами DAG,
  DP разбиений конфликта и DP слияния полос с setup.

## Yosys
Направление каждого свойства задано в исходном RTL. BMC сначала проверяет
достижимость при предположениях, затем ищет нарушение. Положительные схемы на
горизонте требуют SAT предпосылок и UNSAT утверждений в каждом шаге.
У отрицательного контроля намеренно перевёрнут один выходной бит в первом
состоянии при допустимом входном триггере. На первой волне скрининга независимо
проверены 180 VCD. Для новых панелей проверка выполняется при каждом SAT.
Одинаковый математический выход каждого варианта и активный триггер
восстанавливаются напрямую из видимых входов и начального состояния.
Входной guard деления дополнительно проверяется на ненулевой делитель.
Тайм-аут не означает отсутствие нарушения. Отдельный живой запуск на Z3
подтверждает результат BMC. Проволочный аудит сравнивает реальные команды
cvc5, аннотированный dump и replay тех же команд на Z3.

## Программы
У Dafny основная единица — вердикт целой программы. Выход prover model error
делает сеанс непригодным даже при правдоподобной строке с числом доказательств.
Конкретный отрицательный постконтракт `x=9 ⇒ result<9` проверяет эту границу.
Скрипты SMT для Z3 и cvc5 от Boogie сохраняются раздельно.
У дополнительного Why3 штатный драйвер печатает родной VC, и истинность
программы соответствует его UNSAT. Иной формат или невозможность
интерпретировать результат указываются как исключение.
